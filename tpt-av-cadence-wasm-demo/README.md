# tpt-av-cadence-wasm-demo

A WebAssembly smoke test for the `tpt-cadence` decoder crates. It exports one
decode function and one sample-rate function per format through
`wasm-bindgen`, then runs a Node.js harness that checks each format end to end.

**Status:** internal demo, `publish = false`. It proves that the decoders
compile and produce correct output under `wasm32-unknown-unknown`. It is not a
general-purpose WebAssembly API.

## Exports

| Format | Decode (returns `Float32Array`-compatible PCM) | Sample rate |
|---|---|---|
| WAV | `decode_wav_to_f32(bytes)` | `wav_sample_rate(bytes)` |
| AIFF | `decode_aiff_to_f32(bytes)` | `aiff_sample_rate(bytes)` |
| FLAC | `decode_flac_to_f32(bytes)` | `flac_sample_rate(bytes)` |
| MP3 | `decode_mp3_to_f32(bytes)` | `mp3_sample_rate(bytes)` |
| AAC | `decode_aac_to_f32(bytes)` | `aac_sample_rate(bytes)` |
| Opus (Ogg) | `decode_opus_to_f32(bytes)` | `opus_sample_rate(bytes)` |
| Vorbis (Ogg) | `decode_vorbis_to_f32(bytes)` | `vorbis_sample_rate(bytes)` |

Each decode function opens the whole buffer as a cursor and decodes it to the
end, returning interleaved `f32` samples. On any error it returns an empty
array, and the sample-rate function returns `0`. The wrapper deliberately
keeps error handling simple. A real API would stream and propagate typed JS
errors.

## Build and run

From the workspace root:

```sh
cargo build -p tpt-av-cadence-wasm-demo --target wasm32-unknown-unknown --release
wasm-bindgen target/wasm32-unknown-unknown/release/tpt_av_cadence_wasm_demo.wasm \
    --out-dir tpt-av-cadence-wasm-demo/pkg --target nodejs
cd tpt-av-cadence-wasm-demo
node test.js
```

`pkg/` is gitignored, so the `wasm-bindgen` step must run before `node test.js`
in every fresh checkout. Rerun it after changing the exports. CI's `wasm` job
runs the same steps, plus a `wasm-opt -Oz` pass.

## Fixtures

`fixtures/` holds the input files that `test.js` decodes:

- `tone.flac`, `tone.mp3`, `tone.opus`, and `tone.vorbis` are generated by this
  workspace's own encoders.
- WAV and AIFF are synthesized in JavaScript inside `test.js`.
- AAC reads the `tone.aac` file bundled with `tpt-av-cadence-aac`, because the
  AAC encoder is out of scope.

Regenerate the encoder-made fixtures only when the signal or an encoder changes.
The encoders are deterministic, so regeneration reproduces the same bytes:

```sh
cargo test -p tpt-av-cadence-wasm-demo --test gen_fixtures -- --ignored
```

## What the harness checks

- Lossless formats (WAV, AIFF, FLAC) must decode sample-exactly.
- Lossy formats (MP3, Opus, Vorbis, AAC) must report the right sample rate and
  duration, and their level must be within tolerance.
